UniFi-контроллер
Каждая точка становится RF-сенсором — отдельные коробки с netsh не нужны. Контроллер сам говорит, какие BSSID наши, поэтому evil-twin ловится точно, без обучения.
Контроллер видит их как чужие — без этого списка они будут считаться подозрительными.

Добавить хост
Страница может отдавать 200, но писать «идёт обновление» — тогда сервис на деле лежит. Укажи текст (или regex), который есть только на живой странице: нет текста → проверка красная.
Задашь MAC — появится кнопка «Разбудить» на плитке и команда /wake в боте. При сканировании подсети MAC подтягиваются сами.
Если родитель упал — алерты по этому хосту глушатся. Ставь шлюз/свитч родителем для машин за ним: ляжет шлюз — придёт одно сообщение, а не сорок.
Мониторинг по подсетям
Добавь диапазон, нажми «Сканировать» — все живые хосты попадут в наблюдение и будут отслеживаться.
Добавить подсеть
Обычно сюда ставят шлюз этой подсети. Все найденные хосты получат его родителем — и при падении шлюза не завалят тебя алертами.
Свитчи на карте
Тупые (неуправляемые) свитчи монитору невидимы — у них нет IP. Добавь их сюда вручную, чтобы отметить на карте, где что стоит. Потом у нужных хостов выбери этот свитч родителем (в списке хостов выше или при добавлении хоста).
Авто-скан сети
Скан + диф сами по расписанию: новые устройства, исчезновения, смены MAC и конфликты IP ловятся без нажатия кнопки. Учти: периодический ping sweep шумный — если в сети есть IDS, предупреди безопасников. Имена устройств подтягиваются автоматически (DNS/NetBIOS).
Надзор за DHCP
Кто-то воткнул домашний роутер — в сети второй DHCP, у половины офиса «странно не работает». Монитор периодически спрашивает «кто тут раздаёт адреса?» и поднимает 🔥, если ответил кто-то левый. Первый прогон запоминает штатные серверы. Заодно предупредит, если штатный DHCP замолчал.
Штатные серверы: ещё не выучены
Тихие часы
Ночью принтер моргнул — тебя будить не надо. В тихие часы звенят только 🔺критичные хосты; остальное пишется в журнал и приходит утром одной сводкой. Приоритет ставится каждому хосту в списке выше.
Выдержка до алерта
Хост упал → алерт ждёт столько секунд. Вернулся раньше — в телефон не уходит ничего, инцидент остаётся только в журнале. Гасит моргания, которые кончаются сами.
Сохраняется кнопкой в блоке «Защита от алерт-шторма» ниже.
Защита от алерт-шторма
Ляжет свитч — упадут все хосты за ним разом. Без этого в телегу прилетит сорок сообщений подряд.
Упало столько или больше за один цикл → придёт одна сводка вместо кучи алертов.
Хост упал → монитор прогоняет tracert и сверяет соседей по подсети: лёг сам хост или сегмент за роутером. При шторме — одна трасса по хосту-представителю.
«Реакция» = кнопка «✅ Принял» или «🔇» в алерте. Никто не нажал, хост всё ещё лежит → алерт повторится громче, и уйдёт во второй чат, если указан.
Устройства сами кричат о себе в сеть весь день. Монитор молча слушает: новое устройство ловится мгновенно (не ждёт скана), имена железок подтягиваются в карту сети. Ноль пакетов от монитора.
Один раз сменился MAC — замена железки (об этом скажет диф сети). А если адрес мечется туда-сюда между двумя MAC или меняется 3+ раза за час — это два устройства дерутся за один IP. Проверка пассивная: читается ARP-кэш, который монитор и так греет своими проверками.
Детект деградации
Предупреждает до падения. Монитор сравнивает текущий отклик с обычным для этого хоста и кричит, если стало заметно хуже: умирающий диск, забитый канал или перегруженный сервер видно за часы до аварии.

База считается как медиана за неделю — устойчива к случайным выбросам. Пока истории мало, детект молчит, а не гадает.
3 = отклик втрое выше обычного. Меньше 2 ставить не советую — словишь шум.
За сколько последних минут считать «сейчас». Короткое окно = нервно, длинное = поздно.
Окна обслуживания
Плановые работы не должны алертить: «суббота 22:00–23:00 — регламентная перезагрузка сервера». В окне молчат даже 🔺критичные хосты (их же ты сам и ребутаешь), авто-runbook их не трогает. В журнал события пишутся как обычно.

Расписание питания (Wake-on-LAN)
Будит машины по времени: «в 08:30 по будням поднять цех». Работает для хостов с MAC в подсети монитора (WoL-броадкаст между подсетями не ходит). Через 3 минуты монитор перепроверит и скажет, кто не поднялся. Сам монитор разбудить себя не может — для него BIOS «Restore on AC Power Loss».
Добавить правило
Ctrl+клик — выбрать несколько. В списке только хосты с известным MAC.
Авто-runbook — чинит сам
Упал хост с известным MAC → монитор сам шлёт ему Wake-on-LAN, ждёт и перепроверяет. Поднялся — тебе приходит «починилось само, не дёргали зря». Не поднялся — обычный алерт «нужен ты». Половина ночных падений закрывается без тебя.

Внимание: это единственная функция, которая действует сама, без твоей команды. Поэтому по умолчанию выключена — включаешь осознанно.

REST API
Для скриптов и интеграций: любой /api/* эндпоинт с заголовком Authorization: Bearer <токен>. Токен показывается один раз при генерации. Имеет смысл, когда включён пароль (без пароля API и так открыт в LAN). Список эндпоинтов — API.md рядом с кодом.

Интернет и DNS — кто виноват
Три отдельные проверки: шлюз (наша железка), внешний IP (канал провайдера) и резолв имени (DNS). Когда «интернет упал» — алерт скажет, кому звонить: себе или провайдеру.
Укажи DNS-сервером офисный (если есть свой) — монитор поймает именно его смерть: «пинг наружу ходит, имена не резолвятся».
Контроль самого монитора
Выключен
Кто мониторит монитор? Если эта машина ляжет — алерты просто перестанут приходить, а тишина выглядит как «всё хорошо».

Монитор будет пинговать внешний сервис каждые N минут. Пинги прекратились — сервис сам пришлёт тебе алерт.

Как: заведи бесплатный чек на healthchecks.io → скопируй его Ping URL → вставь сюда. Период в сервисе поставь чуть больше интервала ниже.
Версия и обновление
Новый exe присылается через Taildrop и ложится в «Загрузки». Перед заменой — пробный запуск; текущая версия уходит в backup\. Если новая не пройдёт первый цикл проверок за 2,5 мин — вернётся старая сама.
