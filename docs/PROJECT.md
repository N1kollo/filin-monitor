# Филин — описание проекта

**Мониторинг небольшого офиса, который не будит по пустякам и сам поднимает серверы после отключения света.**
Один `.exe` на офисном ПК, управление — из Telegram.

---

## Проблема

В небольшом офисе нет дежурного админа, а инфраструктуры хватает: серверы 1С на Hyper-V, кассы, файловое
хранилище, интернет от провайдера, Wi-Fi, десятки камер на нескольких регистраторах.

Готовые решения не подошли:

- **Uptime Kuma** и аналоги знают только «жив / не жив» по каждому адресу. Когда падает один хост, приходит
  пачка тревог про всё, что на нём крутится, и непонятно, что чинить первым.
- **Zabbix** умеет всё, но это месяц настройки и постоянный шум.
- Ночью сообщения приходят про всё подряд, и к утру их перестают читать — вместе с важными.

## Что делает Филин

| | |
|---|---|
| **Думает сервисами** | Не «192.168.10.32 не отвечает», а «1С Торговля не работает — лежит HV-02». Причину ищет вверх по цепочке «виртуалка → хост». |
| **Одно сообщение вместо шторма** | Что упало, что затронуто и план действий. С кнопкой. |
| **Поднимает сам** | «Поднять упавшие»: сначала будит хосты Hyper-V по Wake-on-LAN, виртуалки встают с ними, потом всё остальное — волнами, в правильном порядке. |
| **Не будит по пустякам** | Тихие часы, выдержка до тревоги, защита от шторма, эскалация критичного. На живом офисе: 18 сообщений за ночь → 0, без потери важного. |
| **Камеры** | Какая камера на каком объекте, кто на связи, стоп-кадр по клику. Регистраторы Dahua — только чтение, пароли до браузера не доходят. |
| **Сеть** | WAN по трём ногам (шлюз / канал / DNS), чужой DHCP, конфликт IP, трасса до упавшего хоста, деградация задержки до падения. |
| **Обновляется сам** | Новая версия — кнопкой в боте: пробный запуск, бэкап, замена. Не прошла первый цикл проверок за 150 секунд — откат, и в Telegram приходит причина. |
| **Сторож за сторожем** | Если умрёт сам Филин, тревогу поднимет внешний healthchecks.io. |

## Откуда взялся

Писался под живой офис: пять подсетей на одном коммутаторе, три хоста Hyper-V с виртуалками 1С, почти сотня
камер на шести регистраторах, Wi-Fi от торгового центра, который на ночь обесточивает точки.

Боевая проверка случилась сама: в здании отключили электричество, на месте никого не было. Серверы
поднимали из Telegram, по одному, по памяти. После этого Филин научился делать это сам.

## Как устроен

- **Python, только стандартная библиотека.** Ни одного пакета из pip — нечему ломаться при обновлении
  и нечего ставить на офисный ПК. PyInstaller нужен только на сборочной машине, а четыре JS-библиотеки
  дашборда (графики и карта сети) вписаны прямо в HTML, чтобы он работал без интернета.
- **Один файл.** PyInstaller-сборка, служба Windows, веб-дашборд без сборки фронтенда.
- **29 модулей, ~8 300 строк** Python, дашборд — один HTML.
- **228 тестов** с заранее известными ответами. Сборка exe проходит только при зелёных тестах.
- **Одна дверь для тревог.** Каждое сообщение идёт через `emit()`: фильтр типа → глушение хоста → окно
  обслуживания. Состояние «что уже сообщено» переживает перезапуск.
- **Монолит разобран скриптом, а не руками.** 7 680 строк → 29 модулей, ни один тест не поменялся.

## Что нашли тесты и эксплуатация

- На русской Windows `ping` мерил время запуска процесса, а не ответ сети: шлюз «54 мс» вместо 1 мс.
- Деградация связи не снималась 14 часов из-за перепутанного состояния.
- Две копии монитора делили один порт.
- Внешний сторож по умолчанию поднимал тревогу только через сутки — нашли, остановив монитор по-настоящему,
  а не тестовым сигналом.
