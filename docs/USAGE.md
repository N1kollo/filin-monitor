# Филин — руководство

Мониторинг доступности серверов с алертами в Telegram. Тёмный дашборд в стиле
торгового терминала, вся настройка — из веб-интерфейса. Ставить ничего не нужно:
только стандартная библиотека Python, ни одного пакета из pip.

- **Проверки:** `ping` · `tcp` (порт открыт?) · `http` (код < 400)
- **Настройка из UI:** хосты, подсети, Telegram, интервалы — ничего не правишь руками
- **Подсети:** задаёшь `192.168.1.0/24`, сканируешь — живые хосты сами попадают в наблюдение
- **Алерты:** Telegram при падении и восстановлении, с порогом против ложных срабатываний
- **Развёртывание:** служба Windows одним `.bat`, либо standalone `.exe` без Python на сервере

---

## Быстрый старт (для теста на этом ПК)

Нужен установленный **Python 3.9+**. Больше ничего.

Двойной клик по **`run.bat`** → открой <http://localhost:8081>.

Или из консоли:

```bash
python monitor.py
```

Дальше **всё в интерфейсе**: жми **⚙ Настройки**.

## Что настраивается в интерфейсе

**Вкладка «Хосты»** — что мониторить. Тип проверки:

| тип | нужно | «жив», когда |
|-----|-------|--------------|
| ping | хост/IP | отвечает на icmp-эхо |
| tcp  | хост/IP + порт | tcp-соединение проходит (сервис слушает) |
| http | URL | http-код < 400 |

> **Совет:** «жив ли сервис» надёжнее всего через `tcp` с портом. `ping` говорит
> только «машина отвечает» — сервер может пинговаться, а приложение на нём лежать.

**Вкладка «Сеть»** — добавь диапазон CIDR (`192.168.1.0/24`), нажми
«Сканировать». Все ответившие хосты добавятся в наблюдение автоматически.

**Вкладка «Telegram»** — мастер настройки (см. ниже).

**Вкладка «Алерты»** — всё, что решает, звенит телефон или нет: тихие часы,
выдержка до алерта, защита от шторма, эскалация, деградация, окна обслуживания,
фильтр по типам, тихое окно точек UniFi, шум за неделю.

**Вкладка «Автоматика»** — Wake-on-LAN по расписанию, авто-runbook.

**Вкладка «Система»** — название, интервал, таймаут, порог падений, вход в панель,
REST API, интернет и DNS, контроль самого монитора, журнал монитора.

> **Выдержка до алерта** (90 с по умолчанию) — хост упал, алерт ждёт. Вернулся
> раньше — в телефон не уходит ничего, инцидент виден только в журнале. Это
> главная защита от морганий: хост, потерявший две пробы подряд и вернувшийся
> на третьей, лежал 25 секунд, а не падал.

## Telegram (2 минуты, всё в интерфейсе)

1. В Telegram: **@BotFather** → `/newbot` → скопируй **токен**.
2. Напиши своему новому боту любое сообщение (иначе он не сможет тебе писать).
3. В дашборде: **⚙ Настройки → Telegram** → вставь токен → «Сохранить токен».
4. Нажми **«Определить чат»** — бот сам найдёт твой чат по сообщению из п.2. Выбери его.
5. «Сохранить Chat ID» → «Отправить тестовое сообщение».

Приходит:
- `🔴 НЕДОСТУПЕН: <имя>` — когда хост не ответил `порог` раз подряд
- `🟢 ВОССТАНОВЛЕН: <имя>` — когда вернулся, с длительностью простоя

Токен — секрет. `config.json` уже в `.gitignore`, в репозиторий не попадёт.

### Смотреть статус прямо в Telegram (с телефона, откуда угодно)

Бот отвечает на команды — не нужен ни дашборд, ни VPN, ни публичный адрес:

| Команда | Что делает |
|---|---|
| `/status` | вся сводка: сколько в строю/упало + список хостов |
| `/down` | только упавшие |
| `/help` | список команд |

Под сообщением — кнопки **«🔄 Обновить»** и **«🔴 Только упавшие»**, обновляют
сводку на месте. Бот отвечает только твоему чату (chat_id из настроек), посторонние
команду не выполнят. Это самый простой способ наблюдать всё с телефона.

## Развёртывание на Windows Server 24/7 (без танцев)

Монитор полезен, только пока запущен. Два пути:

### Путь A — есть Python на сервере
1. Скопируй папку на сервер.
2. ПКМ по **`install-service.bat`** → «Запуск от имени администратора».

Создаётся задача, которая стартует монитор при **каждой загрузке**, даже без входа
в систему. Удалить — `uninstall-service.bat`.

### Путь B — Python на сервере нет вообще (максимально «без бубнов»)
1. На своём ПК с Python: двойной клик **`build-exe.bat`** → соберётся
   `dist\ServerSignalDesk.exe` (один файл, Python внутри).
2. Скопируй на сервер только `dist\ServerSignalDesk.exe` + `config.json`.
3. ПКМ по `install-service.bat` → «Запуск от администратора» (он сам увидит exe).

Готово. Дашборд на сервере: `http://<ip-сервера>:8081`.

## Смотреть с другого компа

Монитор — это веб-сервер, поэтому «мониторить с другого компа» = просто открыть
браузер. Разделение сервер/клиент встроено.

### В той же сети (LAN)
1. На комп-сервере: ПКМ по **`allow-firewall.bat`** → «Запуск от администратора»
   (откроет порт 8081 в брандмауэре).
2. Узнай IP сервера: на нём `ipconfig` → строка **IPv4 Address** (напр. `192.168.1.50`).
3. С любого компа в сети открой `http://192.168.1.50:8081`.

### Извне (из дома / другой сети)
Не пробрасывай порт 8081 в интернет напрямую — панель окажется открыта всему миру.
Правильно:
- **VPN** в рабочую сеть → дальше как в LAN по внутреннему IP. Самый простой безопасный путь.
- **Cloudflare Tunnel** (или аналог) → даёт https-адрес с TLS, порт наружу открывать не надо.
  Хорошо ложится, если такой туннель на инфраструктуре уже есть.

В любом «извне»-варианте **обязательно включи пароль** (ниже).

## Пароль на вход

Без пароля любой, кто открыл дашборд, видит панель и может менять конфиг (включая
Telegram-токен). Для доступа по сети — включи авторизацию:

**Настройки → Система → «Вход в панель»** → логин, пароль, повтор → Сохранить.
Действует сразу, перезапуск не нужен, ты остаёшься залогинен.

Если до дашборда не достучаться (забыл пароль) — ПКМ по **`set-password.bat`**
(или `python monitor.py --set-password`), затем перезапустить монитор.

Пароль хранится как PBKDF2-хеш (200k раундов), сессия — в подписанной cookie
`HttpOnly` + `SameSite=Lax`. Выйти — кнопка «Выйти» в шапке.

Что важно знать про сессии:

- **Смена пароля выкидывает все остальные устройства** — ротируется секрет
  подписи, так что утёкшая кука не переживает смену
- **«Выйти на всех устройствах»** — отдельная кнопка там же
- **5 неверных попыток с одного IP → 429 на 15 минут**

> Пароль защищает панель, но не сеть вокруг неё. Если монитор доступен через общий
> VPN (Tailscale, WireGuard), ограничь доступ к порту 8081 и в правилах самого VPN.

> По LAN логин уходит по http (без шифрования) — для доверенной локалки это нормально.
> Для доступа извне используй Cloudflare Tunnel/VPN, где канал уже под TLS.

## Камеры и регистраторы (вкладка «Видео»)

Филин читает регистраторы Dahua: какая камера на каком объекте, кто на связи, стоп-кадр
по клику. Доступ **только на чтение** — настройки регистраторов он не меняет.

1. Скопируй `nvr.example.json` в **`nvr.json`** рядом с `ServerSignalDesk.exe`
   (или рядом с `monitor.py`).
2. Логин и пароль — во вторые кавычки. Одинаковые на всех регистраторах — заполни только
   `default`, иначе укажи `user` / `password` у конкретного адреса.
3. В `nvrs` — адреса регистраторов и понятные имена объектов («Склад», «Торговый зал»).
4. Перезапусти монитор → вкладка «Видео».

```json
{
  "default": { "user": "viewer", "password": "…" },
  "nvrs": {
    "192.168.20.11": { "name": "Склад" },
    "192.168.20.12": { "name": "Торговый зал", "user": "other", "password": "…" }
  }
}
```

Что важно:

- **Заведи на регистраторе отдельного пользователя только с просмотром.** Админский
  пароль Филину не нужен.
- **Ровно одна попытка входа.** У Dahua блокировка после ~5 неверных паролей, поэтому
  при отказе Филин больше не пробует и пишет «логин отклонён — исправь nvr.json»; новая попытка — только после правки файла.
- **Пароли не уходят в браузер.** Стоп-кадр забирает сам монитор и отдаёт дашборду
  готовую картинку.
- `nvr.json` в git не попадает (он в `.gitignore`). Не выкладывай его никуда.

## Обновление и откат

Новая версия ставится кнопкой, без удалённого рабочего стола.

1. Положи новый `ServerSignalDesk-vX.Y.exe` в **«Загрузки»** на ПК с монитором
   (Taildrop, общая папка, флешка — как удобно) или рядом с текущим exe.
2. Telegram: **Меню → 🔄 Версия и обновление → «⬆️ Обновить до vX.Y»**, или в дашборде
   **Настройки → Система → «Версия и обновление»**.
3. Дальше всё само:
   - **пробный запуск** нового exe (`--version`) — битый файл до замены не дойдёт;
   - текущая версия уходит в **`backup\`** (хранятся три последние);
   - замена файла и перезапуск службы;
   - новая версия должна пройти **первый цикл проверок за 150 секунд**. Не прошла —
     автоматически возвращается старая, и в Telegram приходит, почему.

Вернуться на прошлую версию вручную — там же кнопка **«↩️ Откатить на vX.Y»**.

## Сторож за сторожем (healthchecks.io)

Если умрёт сам монитор, тревогу должен поднять кто-то снаружи.

1. Заведи бесплатную проверку на [healthchecks.io](https://healthchecks.io)
   (или в любом совместимом сервисе с «dead man's switch»).
2. Поставь период **5 минут** и grace **10 минут**. Дефолтное расписание сервиса —
   раз в сутки: с ним тревога придёт только на следующий день.
3. Подключи к нему Telegram или почту в самом healthchecks.
4. В Филине: **Настройки → Система → «Контроль самого монитора»** → вставить Ping URL,
   интервал 5 минут, «Включить» → Сохранить. Кнопка «Пингануть сейчас» проверит связь.

Монитор пингует URL, только пока цикл проверок реально работает: зависший монитор
пинговать перестанет, и сработает внешняя тревога.

Проверять лучше остановкой службы, а не тестовым сигналом: так видно, что тревога
действительно приходит и через сколько.

## Демо без сети

```
python demo/demo.py
```

Дашборд на http://127.0.0.1:8090 — выдуманный офис «Ромашка»: два хоста Hyper-V, 1С, кассы, Wi-Fi, три регистратора с камерами. Работает настоящий монитор, симулируется только нижний слой (ping, TCP, HTTP, DNS, Wake-on-LAN, ARP, регистраторы) — в вашу сеть не уходит ни пакета. Неделя истории засеяна; каждые 5 минут HV-02 «теряет питание» — видно алерт, причину в плитках сервисов и «Поднять упавшие». Данные демо — в `demo/_run/`.
